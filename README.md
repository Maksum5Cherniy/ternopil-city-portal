# Де Тернопіль

Незалежний міський портал Тернополя. Публічна адреса: [deternopil.pp.ua](https://deternopil.pp.ua). Це не офіційний сайт міської ради: редакційні матеріали містять дату й посилання на першоджерело.

## Що працює

- Новини, заклади, локації, карта OpenStreetMap, пошук і афіша з фільтрами за назвою, категорією, датою та вільним входом. Завершені події переходять до архіву.
- Профілі з підтвердженням email, входом, відновленням пароля, обраним, відгуками й сповіщеннями.
- Оголошення користувачів проходять модерацію перед публікацією; власник керує своїми оголошеннями, інші можуть поскаржитися на порушення. Демонстраційних пропозицій у публічному каталозі немає.
- Кабінет закладу, модераторська черга та адмінпанель із керуванням користувачами, ролями, контентом, подіями, закладами й зверненнями.
- Адаптивний інтерфейс, світла й темна тема, sitemap, metadata і структуровані дані сторінок.

Публічні сторінки працюють зі стартовим перевіреним контентом без бази. Реєстрації, кабінетам, оголошенням, відгукам і редактору потрібен Postgres; доставці листів потрібен Resend. Дані мають оновлювати редактори, а події слід звіряти з організаторами перед відвідуванням.

## Архітектура і доступ

Застосунок написаний на TypeScript, React та Next.js App Router. Продукційний сайт розгорнуто через Sites із сумісною збіркою Vinext/Cloudflare Workers, Neon Postgres і Resend. GitHub-репозиторій зберігає версію для звичайного запуску Next.js; його `package.json` і `package-lock.json` відрізняються від маніфестів Sites. Спільні вихідні файли синхронізуються в [PR №2](https://github.com/Maksum5Cherniy/ternopil-city-portal/pull/2).

Сесія зберігається в `httpOnly` cookie. Сервер перевіряє ролі `user`, `moderator`, `owner` та `admin` на кожній захищеній дії. Запити зі зміною даних мають перевірку походження, спроби входу й відновлення доступу обмежуються. Продакшн під'єднаний до Neon через роль `deternopil_runtime` з мінімальними правами; схему змінює окремий власник бази. Деталі грантів наведені в [`docs/runtime-grants.sql`](docs/runtime-grants.sql).

## Локальний запуск

У GitHub-репозиторії:

```bash
npm ci
npm run dev
```

У вихідному проєкті Sites використовуйте його `pnpm-lock.yaml` і `pnpm install --frozen-lockfile`. Для функцій з базою створіть `.env.local` за зразком `.env.example` і налаштуйте власні `DATABASE_URL`, `RESEND_API_KEY`, `EMAIL_FROM`. Змінні й паролі не додавайте до Git. Коли схему вже створено власником бази, використовуйте `DATABASE_SCHEMA_MODE=external`; запуск сервера не повинен виконувати DDL через обмежену роль. Для першого адміністратора задайте `ADMIN_EMAILS` до підтвердження його адреси.

Перевірки:

```bash
npm test
npm run lint
npm run build
```

Інструкції з публікації, налаштування секретів і міграцій: [`docs/deployment.md`](docs/deployment.md). Схема даних: [`docs/postgres-schema.md`](docs/postgres-schema.md).
